# 套版设计与合成细则（通用）

> 由原 video-wrap-design 并入。SKILL.md 的「标准」优先；这里是套版各环节的细则，脚本路径都相对 skill 根目录。

将用户已完成的视频放进品牌套版。设计由生图模型完成；代码只负责视频占位区替换、必要的面板尺寸适配和成片验证。

## 范围与依赖

- 输入：最终视频、产品图标和字标、角色参考、卖点文案、商店标识、目标比例、输出目录。
- 默认交付：1080×1080 方版、1920×1080 横版，输出到用户指定目录下的 `成品`；用户给出其他要求时优先遵守。
- 生图前阅读当前会话提供的 `image-gen` 技能。用 `image_generate` 生成完整套版，模型用 image2.5（gpt-image-2.5-flare），设置不是它就先提醒用户切换；不假设工具一定接受某尺寸。
- 合成工具：Python 3、Pillow、numpy（仅 `wrap_config.py` 量边界用）、FFmpeg、FFprobe；不依赖工作台服务。命令行与模块用法见 [wrap-scripts.md](wrap-scripts.md)。
- 视频内部字幕、选项、进度条、尾板等修改交给 `mm-packager`；剧情翻译交给相应文案技能。

## 核心原则

### 最新指定的源文件是唯一依据

用户说“终版为这个路径”后，必须检查该文件，记录大小、SHA-256、流信息和时长。不能继续用之前的导出，不按文件名或修改时间猜。原声、音乐均随这份终版保留；“不添加BGM”不等于移除源文件已有音乐。要移除音乐需独立音轨或回原工程，不能静音整个视频。

### 用户确认什么，就推进到什么阶段

- “先看翻译”只给英文/中文对照及图标方向。
- “先出图”生成可查看的静态完整设计，明确视频区域为生图示意，等待设计反馈。
- “可以，包装输出”表示已授权合成，不再索要相同确认。
- 沿用对话中已确认的品牌、文案、比例和路径，不重新询问已有信息。只问确实阻塞结果的问题。

### 直接生成完整设计，不手工重排

当用户选择生图设计时，Logo、角色、卖点、功能小图标、商店标识及视频示意一起生成。不要先生成背景，然后用 Pillow、HTML 或 SVG 拼出整张套版。需要纠正拼写或元素布局时，优先用生图编辑，保留已满意部分。

功能小图标属于完整广告设计的一部分，可随整张图生成。若用户另要独立可编辑图标资产，则遵守 image-gen 对矢量资产的规则，用 SVG，并明确它属于额外交付。

**合成阶段允许**：裁出已确认设计的外围面板，按真实视频比例适配面板大小，把生成的视频占位画面全部替换成真实视频。这不是重新设计；不得重画人物、改文案、换Logo或偷偷添加边框。

### 视频贴边，留白放在信息面板内

默认无视频外边距、描边、阴影、圆角、手机框。

- 1:1：视频在左侧，顶、底、左边与画布齐平；品牌面板在右。
- 16:9：视频居中，顶、底与画布齐平；左侧品牌及卖点，右侧角色及下载标识。
- 9:16 视频在1080高输出中的理论宽度607.5px，YUV420编码取608px；方版右侧472px，横版左右各656px。这是约0.08%的像素舍入，不是任意拉伸。
- 若视频比例不同，先按源比例计算。不要盲用608px或裁掉字幕；明显不同的比例需重新布局。
- 模型给的占位区宽度通常不精确。读取真实像素、打开检查并标出边界；禁止照提示词百分比直接当作实际裁切线。
- 面板铺满视频以外的全部区域，所有元素完整显示：不在分界线旁压黑带或遮罩、不缩小面板留出底边侧边；元素贴线时回生图修改，不靠后期遮盖。

### 品牌、文字与角色可追溯

读取并查看原始Logo。优先使用用户提供版本，App图标与字标是两个不同资产，是否都用依用户要求。配色从实际Logo提取，不能凭品牌名猜。

文案逐字沿用确认版本，不私增“免费”等承诺。“真实”可译为 `Feels Real`，不能误译成真人服务。聊天数量必须先核对原数值：1000万=10M，1亿=100M，不能把中文单位照搬到英文广告。

角色参考必须来自用户素材或明确认可的生成图。保持脸型、发型、发色、服装和画风一致，避免模型把视频示意的人物变化带入实际成片。

## 工作流程

1. **检查输入**：定位最终视频和品牌素材，查看角色/Logo，探测视频尺寸、帧率、时长和音轨。用户未给文件时先在已授权项目范围查找，避免扫描整台机器。
2. **确认内容**：整理已确认的翻译、图标语义和版式。必要的待确认项尽早提出；可继续搜集不依赖回答的素材。
3. **生成两个完整设计**：每个比例单独调用 image_generate（不能用 n=2 代表两个不同尺寸）。参考图复制到工具允许的工作目录；提示词采用 [prompts.md](prompts.md)，把真实文字完整列出。
4. **检查预览**：打开生成图，检查所有文字、两个商店标识、人物、贴边、留白。错误用有针对性的图片编辑处理。记录真实尺寸与占位区边界；不把生成画面当作真实视频帧。给用户审的设计图，视频区先换成真实视频帧。图片按用户指定目录归档，给可复制的完整路径，不能只给可能打不开的链接。
5. **合成**：用户认可设计并授权后，按 [config.example.json](config.example.json) 写任务配置。用 `python scripts/package.py 配置.json`。设计为「1:1 视频在左 / 16:9 视频居中」的标准版式时，可直接 `python scripts/wrap.py <视频> <1x1> <16x9> <套版目录> --stem 名`（自动量分界线写 wrap.json 再合成）；量不准会停下，人工核对后加 `--force` 或手改 wrap.json。配置路径相对于配置文件；不得把示例路径当成当前任务输入。输出名已存在时换版本名。
6. **验证**：脚本验证两版尺寸、帧率、帧数、完整解码和原音轨包哈希，抽取检查帧。打开每版至少一张常规画面、一张交互/遮挡关键帧和尾板，确认无占位残留、字幕不裁切、源图未被挤压。通过才称交付完成。
7. **交付**：给每个成品的完整路径、尺寸、时长和检查结果。图片预览阶段不得声称视频已导出。没有验证的项目必须明确说明。

## 合成配置与音频规则

配置包含 source、output_dir、work_dir、variants；每版包含已确认 design、output、size、video_width、各面板裁切 rect 和落位 dest。矩形统一为 `[x,y,width,height]`，按设计图真实像素填写。脚本检查外围面板覆盖完整，且不盖住视频。

默认30fps仅适用于源为30fps；脚本自动读取实际帧率，不强改。视频宽高、坐标须为偶数。源视频需正常显示方向、SAR=1；旋转元数据或非方形像素先规范化到明确的新源文件并重新确认构图。

FFmpeg使用 overlay 的 `shortest=1` 结束背景视频流，**不使用输出级 `-shortest`**，避免丢掉略长于视频的最后一个AAC包。音轨使用 `-c:a copy`，不加音乐、不重编码、不改音量。若容器不兼容，先解释需要转码，不能假报位流一致。

## 测试与维护

触发与回归案例见 [../tests/wrap-cases.md](../tests/wrap-cases.md)。`python tests/smoke.py` 在临时目录测试有声、无声、两个比例及禁止覆盖。需分别报告自动测试和人工检查；不能将路由规则的自查称为实际模型触发测试。

## 已知失败与通用修复

| 实际问题 | 原因 | 规则 |
|---|---|---|
| 用户拒绝手工拼版 | 只让模型出底图，再代码排字，与用户预期不符 | 生图直接做完整设计；只替换视频占位区 |
| 视频四周留框 | 误把留白分配到视频外侧 | 视频顶底贴边，留白在侧栏 |
| 分界线旁出现黑边 | 为让元素离线在后期压黑带、缩小面板 | 面板铺满，间距靠生图构图留出 |
| 生图尺寸不符请求 | 服务返回了不同分辨率 | 用实际像素测量边界，不以请求尺寸推断 |
| 音轨末尾少一个包 | 输出级 -shortest 截到视频结束 | 不用全局 -shortest，比较音频包哈希 |
| 英文尾板出现“万” | 中文数值单位未本地化 | 核对数值后转换为M等英文单位 |
| 图片链接打不开 | 客户端不支持本地file URI | 图片复制到目标目录，并给原始完整路径 |
